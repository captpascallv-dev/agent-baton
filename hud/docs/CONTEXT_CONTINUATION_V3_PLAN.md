# Codex Usage HUD — 续接风险 V3

状态：`COMPLETE — 已发布并通过真实本机验收`
日期：2026-08-13

## 修正原因

V2 的等级只衡量最近三次压缩后的结构承载，却在界面上表现成会话整体健康。真实 Concerto Lead
虽然结构等级为 A-，但已累计约 3.5B raw tokens、数百个回合，并出现用户明确观察到的多次漂移。
结构稳定不能证明执行可靠，因此必须拆分信号。

## 冻结产品逻辑

1. **结构承载**：沿用 V2 的压缩后底座、底座趋势和双续航规则，只表达上下文结构。
2. **长会话风险**：自动使用累计 raw token、已聚合回合、近 48 小时 token 和可靠回合强度；
   仅比较本机同模型主会话，样本少于 10 个时不可用。raw token 不单独触发建议。
3. **实际漂移**：用户三选一标记 `未评估 / 偶发漂移 / 连续明显漂移`。只保存 thread id、档位、
   UTC 时间；不保存说明文字。偶发漂移最低 B-，连续明显漂移为 C。
4. **综合建议**：取三项最差等级，不平均，不把未评估解释为零漂移。

长会话自动门槛使用本机相对值：历史 token 与回合同时进入前 10% 且均达到中位数 3 倍时最低
B+；两项进入前 3% 且均达到中位数 10 倍，或高历史负担同时叠加极高的近 48 小时强度时最低
B-。近 48 小时强度不能单独把一个新会话判为长会话风险。

## 实现与验收

- SQLite schema v8 新增 `session_drift_assessments`，无正文列。
- 所有统计和写入继续在后台队列执行；人工按钮使用 single-flight，连续点击不堆积写任务。
- 自动测试覆盖结构等级不变、长会话 B-/人工 C 覆盖、标记清除与重启持久化、隐私 schema、
  20 次快速点击和 WPF Dispatcher 响应。
- 发布前以真实本机数据库核对 Concerto Lead 的自动长会话风险，并完成完整测试、UI 截图、
  self-contained 发布、重启不丢失验证。

最终结果：77/77 自动检查通过；正式 EXE 单实例启动正常；Concerto Lead 的人工漂移标记在
重启后仍为“连续明显漂移”，综合建议为 C；20 秒稳态采样约占单核 0.47%。
